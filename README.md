# Arthapalana portfolio intelligence

Private portfolio dashboard for NocoDB `PortfolioTransactions`, with research generated by the official Codex SDK on this machine using the existing ChatGPT subscription login.

## Research and billing

The hosted application no longer calls the OpenAI Responses API, accepts API keys, or falls back to API billing. The local runner checks `codex login status` before each report and requires ChatGPT authentication. It excludes API keys, alternate-provider credentials and dashboard secrets from the Codex child environment. `forced_login_method=chatgpt`, `model_provider=openai`, and an isolated CLI invocation prevent a provider or authentication fallback. Model overrides unavailable to the subscription fail explicitly.

Research consumes the user's **Codex subscription allowance**, subject to its limits. No claim of unlimited/free model usage is made. An unavailable session or exhausted allowance stops research; the last successful report stays visible.

## Data and recommendations

- Every NocoDB page is read; no records are changed and no trades are placed.
- FIFO lots, explicit CASH ledger, separate portfolios, household exposure and current-FX valuations.
- Yahoo market-session quotes, currency conversion, timestamps, price histories and corporate-action reconciliation checks. Prices can be delayed; the weekday-session check does not include an exchange holiday calendar.
- Declarative risk signals remain independent of the model. The runner applies the original Jarvis prompt with strict evidence and locked-position instructions, returning structured per-position recommendations.
- The server validates output, rejects unknown/duplicate positions, fills missing coverage with Review, preserves the ORCL ESPP lock and blocks unsupported buys/exits. Deterministic quantities are the execution reference.
- Forward XIRR, moat, governance, bank-specific metrics, news and full five-year forensic checks are unverified where not supplied. New-stock discovery runs the 18 Jarvis sector-aware sub-screens across NSE and NYSE/Nasdaq (A: quality compounders, B: GARP, C: value/re-rating). It captures up to 30 matches per screen and performs 24 diversified deep dives, excluding all current household holdings and ORCL. Financial statements, forward EPS, analyst ratings, 72-hour news and nearby earnings/dividend events feed Jarvis’s deterministic forward-risk gate. Missing evidence remains visible; passing a screen alone is not an entry recommendation.

## Architecture

Vinext / React / TypeScript on Cloudflare Workers, D1 persistence, owner-private Sites gateway. `/api/portfolio` serves live data; `/api/settings` saves model/timing; `/api/analysis` queues research and reads the last successful result. `/api/runner` is an outbound-only machine protocol protected by both the private Sites gateway and a separate shared secret.

The runner polls every 30 seconds. Before Codex research it runs `runner/discovery.py` in the isolated Python runtime (`runner/requirements.txt`). The shared-secret protocol registers the screened evidence against the active lease; Codex can select only those candidates. The server downgrades watchlist/rejected names from entry, and the browser sizes only eligible, Codex-selected names with fresh quotes/FX, 5–15% position sizes, whole Indian/four-decimal US shares, household caps, 25% cyclical / 20% commodity / 15% Category C limits, and a price-gap check. Unallocated or sub-meaningful amounts stay in reserve. This is conditional research, not automatic trade execution. A singleton D1 job queue, atomic claim and expiring/renewed lease prevent duplicate work. A 270-second screening timeout and nine-minute model timeout prevents hung runs; upload retries reuse the same report and lease. Failed research never overwrites the last good report. Browser refreshes never make model calls directly.

Portfolio prices refresh every five minutes while the dashboard is open. The local service generates research at the configured interval even when the page is closed, **while this machine is awake, connected, and the user service is active**. A user service starts with the user's session; the machine must not be asleep. Default interval is one hour. Settings supports pause, model override and interval changes; a manual request can run even when automatic research is paused.

## Local runner

- Official SDK dependency: `runner/package.json` and lockfile, pinned to 0.166.0.
- Codex executable: `/home/snemmani/.local/bin/codex` (existing signed-in installation).
- User service: `arthapalana-codex-runner.service`.
- Local-only runtime: `.runner-runtime/bin/node`.
- Local-only connection: `.runner-private/connection.json`, mode 0600 within a mode-0700 directory. Contains only private dashboard service access and the runner shared secret. **ChatGPT credentials are not copied or uploaded**; they remain in Codex's own credential store.
- `.runner-private/research-contract.mjs` is generated from `lib/runner-contract.ts` by `node runner/build.mjs`.

The SDK runs with shell, external app, plugin, hook, web-search and multi-agent tools disabled. Research uses the supplied financial snapshot only. Codex runs read-only with no approvals or filesystem mutations, in an empty work directory. User/project config and rules are excluded; API credentials are never forwarded.

Manage the service:

```
systemctl --user status arthapalana-codex-runner
systemctl --user restart arthapalana-codex-runner
systemctl --user stop arthapalana-codex-runner
journalctl --user -u arthapalana-codex-runner -n 30
```

After updating runner source, run `node runner/build.mjs` and restart the service. `runner/install-local.py` installs the user service and persistent Node runtime, taking connection JSON on hidden stdin. It does not change global Codex configuration or authenticate with an API key. If the ChatGPT session expires, run `codex login` interactively, then restart the service.

## Hosted security and migration

Runtime secrets: `NOCODB_TOKEN`, `CF_ACCESS_CLIENT_ID`, `CF_ACCESS_CLIENT_SECRET`, `RUNNER_SHARED_SECRET`. Configure through native Sites environment settings, never browser code or `.openai/hosting.json`. The old `SETTINGS_ENCRYPTION_KEY` is removed. Old stored API keys are nulled by the new settings initialization; legacy API reports are not displayed as Codex reports.

The Sites gateway is the owner-only authorization boundary; do not broaden its audience without adding per-user authorization and data separation. Browser mutations verify Origin. The machine endpoint requires its shared secret and the Sites service-access header. Its secret is not given to the model. The machine holds no inbound listening port.

USD costs and gains use the current USD/INR rate, matching Jarvis's supplied convention; these are not historical-FX tax figures. Corporate actions are checked, never automatically rescaled.

## Checks and build

Requires Node >=22.13. Root dependencies: `npm ci`; runner dependencies: `npm ci --prefix runner --ignore-scripts`.

```
npx tsc --noEmit
./node_modules/esbuild/bin/esbuild tests/engine.test.ts --bundle --platform=node --format=esm --outfile=/tmp/arthapalana-engine-test.mjs
node /tmp/arthapalana-engine-test.mjs
node tests/subscription.test.mjs
./node_modules/esbuild/bin/esbuild lib/ai.ts --bundle --platform=node --format=esm --outfile=/tmp/arthapalana-runner-api.mjs
node tests/runner-api.test.mjs
```

Tests cover FIFO/cash accounting, stale/missing data, subscription-only authentication, credential isolation, origin checks, queue/lease races, output validation and report persistence. The server tests explicitly fail if a hosted OpenAI API call is attempted. A separate live SDK smoke test and real portfolio run verify subscription authentication end to end.

Schema changes are in Drizzle migrations; hosted publishing applies them. For local preview after a build, apply pending SQL in order using the starter's Wrangler D1 local command. Production builds/publication use the Sites workflow and preserve the starter `sites()` integration.

## Appearance

Auto follows `prefers-color-scheme` and updates when the device theme changes. The top-bar selector supports Auto, Light and Dark; the preference is stored only in this browser. Both themes use subdued surfaces and semantic positive/negative chart colors.

Discovery endpoint: `/api/discovery` reads the last persisted candidate evidence and Codex selections while refreshing their quotes and USD/INR. Report evidence is not silently refreshed or fabricated. A report older than six hours cannot size a new entry. Re-run research if a price rises more than 5% from the research price. If screening fails, its errors are shown and cash is retained.
